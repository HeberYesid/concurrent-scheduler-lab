# ADR-004: Patrón Command para Trazabilidad y Verificación del Heap

## Estado
Aceptado

## Contexto
El simulador del scheduler concurrente realiza múltiples modificaciones sobre la cola de prioridad `MaxHeap` (inserción de procesos, extracción del máximo y envejecimiento de elementos). Para propósitos de depuración, análisis fino de rendimiento, auditoría de ejecución y en particular para realizar pruebas unitarias rigurosas, es de suma importancia contar con un historial estructurado de los cambios y la posibilidad de deshacer operaciones (*rollback*) sin corromper la consistencia interna.

## Decisión
Se decide aplicar el patrón de diseño **Command**. Cada operación destructiva sobre el heap se encapsula en una clase que implementa una interfaz `SchedulerCommand`.
La interfaz base será:
```java
public interface SchedulerCommand {
    void execute();
    void undo();
}
```

Se implementarán las siguientes variaciones concretas de comandos:
1. `InsertProcessCommand`: Agrega un elemento al heap y almacena su posición para revertir en el `undo()`.
2. `ExtractMaxCommand`: Extrae el proceso con mayor prioridad efectiva y guarda su estado para reinsertarlo en la posición correcta en el `undo()`.
3. `ApplyAgingCommand`: Ejecuta el envejecimiento de todos los elementos y el heapify de Floyd. Para el `undo()`, guarda un *snapshot* del estado de prioridad previo de todos los elementos del heap.

Un gestor `CommandHistory` registrará los comandos ejecutados, limitando el tamaño máximo de almacenamiento en memoria para evitar problemas de consumo excesivo en simulaciones a gran escala ($N = 500.000$).

## Alternativas Rechazadas
1. **Registro por Bitácoras de Texto (Logging Simple)**:
   - *Desventaja*: Informa sobre lo ocurrido pero no permite reconstruir programáticamente el estado anterior del heap ni realizar aserciones detalladas de *rollback* en la batería de pruebas.
2. **Event Sourcing Completo**:
   - *Desventaja*: Excesivamente complejo. Implica persistencia física de eventos, snapshots a nivel de persistencia externa y frameworks pesados, lo cual es innecesario para un simulador de algoritmos concurrentes en memoria.

## Consecuencias
- **Ventajas**:
  - Habilita pruebas unitarias avanzadas que validan el comportamiento dinámico del heap ejecutando una operación, afirmando estados intermedios y revirtiendo la operación para asegurar la consistencia.
  - Ofrece auditoría y depuración determinista ante fallos complejos en el flujo del scheduler.
- **Riesgos y Mitigación**:
  - El almacenamiento de snapshots para `ApplyAgingCommand` puede ocupar memoria considerable bajo $N = 500.000$. Como mitigación, el historial de comandos para revertir se limitará opcionalmente solo durante la fase de ejecución de pruebas o depuración, desactivándolo en benchmarks de producción de JMH para optimizar la asignación de memoria.
